The mission

The Giveaway Mystery

In the 6/15 huddle Priya said: "Honestly the system shows more than fifteen thousand delivered, so we should be covered." The auto-recap repeated it. Riverbend Health Partners is paying $110,000 for a guaranteed 15,000 bobbleheads.

You have two workbooks that should tell the same story but don't: Marketing's Promo Allocations & Requests and the warehouse's Fulfillment & Deliveries export. They contain deliberately planted problems: a duplicate record, inconsistent identifiers, a unit-of-measure trap, damaged goods, a late pallet, a delivery against a cancelled request and a missing fulfillment entry, plus a short ship and two false positives. Your job is to reconcile them, build an exception report you'd stake your name on, and work out which problem everyone else will miss.

Game plan

  • Choose Analyst for multi-file investigation and Copilot in Excel for direct workbook changes
  • Define matching keys and reconciliation rules before running any analysis
  • Find duplicates, missing entries, inconsistent IDs and unit mismatches
  • Separate reliable matches from uncertain ones
  • Build formulas, a summary and a chart with Copilot in Excel, then review every change
  • Prove the result with independent control totals

Analyst The analytics department

A reasoning agent that writes and runs Python against files you give it. Best when you need to compare several files, explore, explain and chart, and see the code it used. It does not change your workbook.

Copilot in Excel The groundskeeper

Works inside one open workbook: adds formula columns, highlights, sorts, builds PivotTables and charts. Best when the deliverable is a working, auditable workbook other people will open.

Part A · Analyst: run the reconciliation

Roughly 15 minutes. You'll make Analyst show its work at every step: structure first, rules second, results third.

  1. Scout the files before you swing

    Open Analyst, attach both workbooks, and ask it to describe the data before it analyzes anything.

    I've attached two workbooks for the Riverfront Rally Weekend (June 18-20, 2027): 1) Promo_Allocations_Requests.xlsx (Marketing's plan) 2) Warehouse_Fulfillment_Deliveries.xlsx (the warehouse's delivery export) Before doing any analysis: - List every sheet in each file with its row count and columns. - Tell me which columns could be used to match records between the two files. - Point out any data quality issues you notice in the identifier columns (formats, spacing, casing, units). Do not reconcile anything yet.
    What you should see
    • Sheets: Requests, Gate Allocations, Item Master, Sponsor Commitments | Deliveries, Inventory On Hand (plus README sheets)
    • Proposed key: Request ID + Gate ↔ Request Ref + Destination
    • Noticed issues such as PR1043, pr-1043, 1043, trailing spaces, BBH-RETRO-27 vs BBH-RETRO27, and a CS unit

  2. Write the rules down: the umpire's rulebook

    The single most important move in any reconciliation is to agree the matching rules before you see the answer. These come straight from the Ops Playbook:

    1. Normalize Request IDs: strip spaces, uppercase, keep the 4 digits → PR-####
    2. Normalize SKUs: uppercase, remove hyphens and spaces, map to the Item Master
    3. Convert units: if UOM = CS, multiply by the Item Master case pack
    4. Remove duplicates: a repeated Delivery ID is a duplicate, even if other fields differ
    5. Distributable = Qty − Damaged Qty
    6. Late = not available: a delivery dated after the game date doesn't count for that game
    7. Tolerance: within ±1% per gate = MATCH; outside = EXCEPTION
    8. Vendor services (fireworks) expect no warehouse delivery
    9. Confidence: label each match Exact, Normalized (needed R1–R3) or No match
    Reconcile planned gate allocations against warehouse deliveries using EXACTLY these rules: R1 Normalize Request IDs: trim, uppercase, keep the 4 digits, format as PR-####. R2 Normalize SKUs: uppercase, remove hyphens and spaces, map to the Item Master SKU. R3 If UOM = CS, convert to units using the Item Master case pack. R4 A repeated Delivery ID is a duplicate - keep only the first occurrence. R5 Distributable qty = Qty - Damaged Qty. R6 Deliveries dated after the request's Game Date do not count toward that game. R7 Per Request ID + Gate, distributable within +/-1% of Allocated Qty = MATCH, otherwise EXCEPTION. R8 Requests with Fulfillment Type = Vendor Service expect no delivery. R9 Label each match Exact, Normalized (needed R1-R3) or No match. Output one table at Request ID + Gate level with: Request ID, Item, Gate, Request Status, Allocated, Delivered (units), Damaged, Late, Distributable, Variance, Variance %, Match confidence, Result, and a one-line Reason. Then list every row you excluded or changed (duplicates, conversions, late deliveries) with the Delivery ID. Show the Python you used.

Part B · Copilot in Excel: build the exception workbook

Roughly 18 minutes. Analyst found the story; now build a workbook that keeps working when tomorrow's export arrives, with live formulas instead of a static answer. Each step has a Copilot prompt and, if Copilot struggles, the formula to fall back on.

  1. Open the starter workbook

    Copilot in Excel works inside one workbook, so the kit includes Rally_Reconciliation_start.xlsx: the allocations workbook with the warehouse Deliveries table already added as tblDeliveries. Open it from OneDrive in Excel (AutoSave on) and open Copilot. In Excel for the web, if there's no Copilot button on the ribbon, use the round Copilot button at the bottom-right of the grid; the pane opens as Let's edit your workbook. Leave the mode dropdown above the chat box on Allow editing (the other choices are Plan and Chat only).

    Not in OneDrive yet? Attach the file to a Copilot Chat message (uploads are saved to OneDrive in Microsoft Copilot Chat Files), click the file card, then choose Open in Excel.

    If a yellow Clean Data with Copilot banner offers suggestions for the Deliveries sheet, dismiss it for now. Accepting its suggestions would change the raw data, and you want the messy Request Refs and SKUs left as they are so your helper columns show what was normalized.

    Doing this with your own data? How to build the combined workbook yourself

    First save a copy of the allocations workbook (File → Save a copy; in Excel for the web, File → Create a Copy → Create a copy online) so Analyst's original stays untouched. Open the copy, add a sheet named Deliveries, and paste the warehouse table into it. If the pasted data isn't already a table, press Ctrl+T. Then rename it tblDeliveries in Table Design.

    Scouting report

    Named tables (tblRequests, tblGateAllocations, tblItems, tblDeliveries) give Copilot and your formulas unambiguous references like tblItems[Case Pack (units per case)], and they grow automatically when new rows arrive.

  2. Clean the keys with helper columns

    In tblDeliveries, add these calculated columns: 1. "Clean Request ID" - "PR-" followed by the last 4 characters of the trimmed Request Ref. 2. "SKU Key" - the SKU in uppercase with hyphens removed. 3. "Case Pack" - look up the case pack from tblItems by matching SKU Key to the tblItems SKU with hyphens removed. 4. "Qty EA" - if UOM is CS, Qty multiplied by Case Pack, otherwise Qty. 5. "Duplicate?" - "Duplicate" if this Delivery ID already appeared in an earlier row, otherwise blank.
    ColumnFormula
    Clean Request ID="PR-"&RIGHT(TRIM([@[Request Ref]]),4)
    SKU Key=UPPER(SUBSTITUTE(TRIM([@SKU]),"-",""))
    Case Pack=XLOOKUP([@[SKU Key]],SUBSTITUTE(tblItems[SKU],"-",""),tblItems[Case Pack (units per case)],1)
    Qty EA=IF([@UOM]="CS",[@Qty]*[@[Case Pack]],[@Qty])
    Duplicate?=IF(COUNTIF(INDEX([Delivery ID],1):[@[Delivery ID]],[@[Delivery ID]])>1,"Duplicate","")
    Check it

    Exactly one row is flagged Duplicate (the second DLV-2222, with Notes "Re-scanned at dock"). DLV-2212 shows Qty EA = 4,000. Every Clean Request ID has the form PR-#### (for example, PR-1043).

  3. Apply the game-day rules

    In tblDeliveries, add: 1. "Game Date" - look up Game Date from tblRequests using Clean Request ID. 2. "On Time?" - "LATE" if Delivery Date is after Game Date, otherwise "On time". 3. "Distributable EA" - 0 if the row is a Duplicate or LATE, otherwise Qty EA minus Damaged Qty. Then highlight LATE and Duplicate rows in light red.
    ColumnFormula
    Game Date=XLOOKUP([@[Clean Request ID]],tblRequests[Request ID],tblRequests[Game Date],"")
    On Time?=IF([@[Game Date]]="","n/a",IF([@[Delivery Date]]<=[@[Game Date]],"On time","LATE"))
    Distributable EA=IF(OR([@[Duplicate?]]="Duplicate",[@[On Time?]]="LATE"),0,[@[Qty EA]]-[@[Damaged Qty]])
    Check it Tested live in M365 Copilot · Nov 2026

    Exactly two rows turn light red: the second DLV-2222 (Duplicate) and DLV-2234 (delivered 6/21 for the 6/20 game, LATE). Both show Distributable EA = 0. Select the Distributable EA column: the status bar Sum should read 63,400. Check how the highlight was applied (Home → Conditional Formatting → Manage Rules): a rule picks up new rows, a fixed fill doesn't.

  4. Build the exception report on the allocations table

    In tblGateAllocations, add these columns: 1. "Distributable Delivered" - sum of tblDeliveries[Distributable EA] where Clean Request ID matches Request ID and Destination matches Gate. 2. "Variance" - Distributable Delivered minus Allocated Qty. 3. "Variance %" - Variance divided by Allocated Qty, formatted as a percentage. 4. "Request Status" - look up Status from tblRequests. 5. "Recon Status" - if Request Status is Cancelled: "DELIVERED VS CANCELLED" when anything was delivered, else "Cancelled - OK". Otherwise "Match" when the absolute Variance % is 1% or less, else "EXCEPTION". Color Recon Status: green for Match, red for EXCEPTION, amber for DELIVERED VS CANCELLED.
    ColumnFormula
    Distributable Delivered=SUMIFS(tblDeliveries[Distributable EA],tblDeliveries[Clean Request ID],[@[Request ID]],tblDeliveries[Destination],[@Gate])
    Variance=[@[Distributable Delivered]]-[@[Allocated Qty]]
    Variance %=IFERROR([@Variance]/[@[Allocated Qty]],0)
    Request Status=XLOOKUP([@[Request ID]],tblRequests[Request ID],tblRequests[Status])
    Recon Status=IF([@[Request Status]]="Cancelled",IF([@[Distributable Delivered]]>0,"DELIVERED VS CANCELLED","Cancelled - OK"),IF(ABS([@[Variance %]])<=0.01,"Match","EXCEPTION"))

Part C · Take-home: do bobbleheads actually move the turnstiles?

Take-home, or a demo if time allows. Leadership will ask whether these promotions are worth it. Use Analyst on Promo_Attendance_History_2025_2026.xlsx (163 rows of fictional home games) to find trends and outliers, and to avoid the most common analytics mistake in sports.

  1. Clean before you conclude

    Analyze the Game Log sheet in Promo_Attendance_History_2025_2026.xlsx. Before any analysis, run data quality checks and report: duplicate Game IDs, impossible values (ballpark capacity is 42,000), and missing values. Propose a fix for each issue and tell me how much each one would distort the 2026 season total if left uncorrected. Do not drop or change anything until I confirm.
    Planted issues you should catch
    • G2026-019 (Sun 5/3/2026): Tickets Sold 300,008, an extra zero on 30,008. It inflates the 2026 total by 270,000 (+10.8%).
    • G2025-024 (Sat 5/17/2025): the bobblehead game appears twice.
    • G2026-047 (Wed 7/1/2026): Scanned Attendance is blank (scanner outage), so no-show and per-cap values are missing.
       

  2. Compare fairly: the same-day test

    Using the cleaned data, estimate the attendance lift for each promotion type. Important: promotions are not randomly scheduled (bobbleheads are on Saturdays, fireworks on Fridays), so compare each promotion against games on the SAME day of week, using TWO baselines: (1) same-day games with NO promotion, and (2) all other same-day games without that promotion type. Report both. Show: a naive comparison (promo average vs all non-promo games) next to the fair same-day comparison, plus game counts. Then show merchandise per cap and no-show rate by promotion type and by weather. Chart the fair comparison. Call out where sample sizes are too small to trust.

Best answer to the challenge

The bobblehead shortfall. It's the most likely to be missed because every surface signal says "covered": the naive total is over plan (16,200), Priya said so in the huddle, and the recap repeated it. The damage lives in a separate column and in an email nobody did the math on (E12). Impact: the largest sponsor ($110K) gets 600 fewer bobbleheads than contracted. That means a $4,800 credit or a replacement promotion night, and real relationship risk, with zero warehouse stock to fix it. Strong runner-up: the 6/21 mini bat pallet. It's the easiest fix in the building (the stock is in the warehouse), but only if someone spots the date.

Common Copilot misses to watch for

  • De-duplicating on all columns (misses DLV-2222 because Request Ref and Notes differ)
  • Reporting towels as 3,910 short (UOM not converted)
  • Calling fireworks "missing fulfillment"
  • Counting the 6/21 pallet as delivered because its Qty is in the table
  • Treating PR-1057's "Approved" status as fact. Ask who approved it.
