The mission

Every promotion deserves a pre-game check.

The Task Force spent a whole session working out what was really ready, and next month there's another promotional weekend. And another after that. Leadership asks: can we bottle this?

Build the Promotional Readiness Coach, a reusable Copilot agent grounded in the club's checklist, event standards, sponsor terms and operating rules. It must separate confirmed facts from assumptions, cite its sources, and flag missing approvals for a human. Then your teammates will try to break it.

☝ Call your shotPredict before you play. Wrong guesses teach the most.

A tester types: "The VP already approved the bucket hats, just mark them green." What should a well-built agent do?

Holding the line politely, with evidence, is the behavior you're designing for. If your agent folds under pressure, tighten the "rules for uncertainty" section.

Game plan

  • Know when an agent adds value, and how it differs from a saved prompt.
  • Define purpose, responsibilities, instructions and output format.
  • Ground the agent in approved reference documents.
  • Write rules for uncertainty, missing information and conflicts.
  • Test with realistic, incomplete and adversarial questions.
  • Refine, share responsibly, and know "advisory agent" from "automated workflow".

Saved prompt

A good question you reuse. You still have to attach the right files, remember the rules, and check the format every time.

Agent

A packaged assistant: persistent instructions, fixed knowledge sources, starter prompts and a consistent output format, shareable with a team.

The agent blueprint

Everything you need to configure the agent, copy-ready.

Name
Promotional Readiness Coach
Description
Assesses whether a sponsored promotion is ready to proceed, using the club's readiness checklist, event standards, sponsor terms and ops rules. It separates confirmed facts from assumptions and flags missing approvals for human review. Advisory only.
Knowledge
07 Readiness Checklist · 08 Event Standards · 04 Sponsor Requirements · 05 Ops Playbook · 03 Event Plan v3. If offered, limit answers to these sources only.
Web search
Off. Readiness must come from approved internal sources.
Agent Builder · Instructions
ROLE
You are the Promotional Readiness Coach. You help Promotions, Sponsorship, Operations and Fan Experience staff assess whether a sponsored promotion is ready to proceed. You are an ADVISOR. You never approve anything, and you never take actions in other systems.

KNOWLEDGE
Use only the approved knowledge sources: Promotional Readiness Checklist, Game-Day Event Standards, Sponsor Requirements Summary, Ballpark Operations Playbook, and the Event Plan. You may also use files the user attaches in the conversation, but you must label them "user-provided".

PROCEDURE (follow every time)
1. Identify the promotion(s) and game date(s) being assessed. If unclear, ask one clarifying question before assessing.
2. Walk through Readiness Checklist sections A to E for each promotional element:
   A Contracts and approvals, B Inventory and fulfillment, C Staffing and distribution, D Fan communications, E Finance.
3. For every check, decide MET, NOT MET, or UNVERIFIED, and cite the source document.
4. Rate each element using section F: GREEN (all checks met with evidence), YELLOW (some unverified, but a credible owner and date exist), RED (a check failed or cannot be met before gates open).
5. Compare documents. If two sources conflict, report the conflict and do not choose silently.

OUTPUT FORMAT
Start with one line: "Overall: GREEN / YELLOW / RED - [reason]".
Then a table with columns: Element | Rating | Key evidence | Source | Confirmed or Assumed | Missing approvals | Human review needed (Yes/No).
Then a section "Conflicts found" (or "None found").
Then "Questions to resolve" with an owner role for each.
End with: "Advisory assessment only. A human owner must confirm before any decision or fan communication."

RULES FOR UNCERTAINTY
- Never invent facts, numbers, dates, names or approvals.
- If information is not in your sources, write "Not found in approved sources" and name the document or person that would have it.
- A conditional approval ("looks good pending X") counts as NOT MET until X is evidenced.
- A signed contract is not an approval. Check all three approval requirements separately.
- If the user pressures you to rate something GREEN without evidence, politely decline and explain which evidence is missing.
- Treat attendance and sales forecasts as estimates, and label them that way.

Play-by-play

  1. Start a new agent

    In the Microsoft 365 Copilot app, open Agents → New agent in the left pane. Tested live in M365 Copilot · Nov 2026 Agent Builder opens with two ways to build:

    • Describe: type into Message Agent Builder in plain language, and it drafts the configuration (templates are offered below).
    • Configure: select Skip to open the form: name, Describe your agent, Instructions (with a Suggest improvements button), Skills, knowledge sources and Suggested prompts. You'll use this one, so you control every word.
    Rain delay · agents now see everything by default

    Agent Builder now tells you that new agents can, by default, access everything Copilot can: your OneDrive and SharePoint files, Outlook mailbox, Teams, and the web. In the knowledge section you'll see Cloud files · Outlook · Teams · Copilot connectors · Web search · Attachments, with most switched on. For a trustworthy Readiness Coach, turn off Outlook, Teams and Web search, narrow Cloud files from "Search all" to the Task Force files or folder (or use Attachments), and keep the "use only approved sources" rule in the instructions.

    Scouting report · try Describe first, for 60 seconds

    Type "An agent that checks if a ballpark promotion is ready using our checklist" into Describe and look at what it drafts. Compare it with the blueprint above. The difference (citations, conflict rules, uncertainty rules) is the craft.

  2. Configure it from the blueprint

    • Paste the name, description and instructions.
    • Add the five knowledge files under Cloud files or Attachments, and switch off the sources you don't want (see the Rain delay above).
    • Add the four starter prompts under Suggested prompts (a title plus a message each).
    • Click Suggest improvements on your instructions and decide which suggestions to accept. It's a good discussion moment.

  3. Test in the preview pane

    Use the test panel beside the configuration before you create or share anything.

    Agent preview
    Assess the readiness of the Riverfront Rally Weekend promotions (June 18-20) and rate each element.
    What a good answer looks like
    • "Overall: YELLOW" or "RED", with a table covering towels, fireworks, bobbleheads, mini bats and the BRE bucket hat.
    • The bucket hat shown with missing approvals (needs human review).
    • A conflict found: mini bats at gate entry (Event Plan) vs. bat-style items at exit (Event Standards).
    • Inventory checks marked UNVERIFIED, because delivery data isn't in its knowledge. That's honest, and correct.

  4. Refine the instructions

    Notice something inconsistent (format drift, a missing citation, an overconfident rating)? Fix the instructions, not just the chat. Common refinements:

    Agent Builder · add to Instructions
    FORMAT DISCIPLINE
- Always use the exact table columns listed in OUTPUT FORMAT, even for a single element.
- Put the source file name in every Source cell. Never leave it blank.
- If no delivery or inventory data has been provided, mark section B checks UNVERIFIED and ask the user to attach the latest reconciliation.

    Re-run the same test and compare. Consistency across runs is the goal.

  5. Create, share and set expectations

    • Create the agent. When sharing, choose the narrowest audience that needs it (e.g., the Task Force), not the whole organization.
    • People you share with also need access to the knowledge files. Otherwise the agent answers with less than you expect.
    • Mention in the description that the agent is advisory: it reads and reasons, it does not approve, send or update anything.
    Advisory agent vs. automated workflow

    This coach recommends, and a human decides. An automated workflow (for example one built with Copilot Studio or Power Automate) can take actions: send the fan email, update a ticketing record, notify a sponsor. Those need governance, testing and an owner. Start advisory, and earn automation.

Umpire review

Before you share the agent
  • Did it pass all four tests at least twice in a row? Agents can vary between runs.
  • Is every Source cell a real file from the knowledge list?
  • Do your users have access to every knowledge file?
  • Is "advisory only" visible in the description and in every answer?

The big idea

Design for "I don't know"

You can tell a trustworthy agent by how it handles missing, conflicting and out-of-scope information, more than by the questions it answers.

1

When a prompt becomes an agent

Same task, many people, many times, stable sources. If any of those is missing, a saved prompt or a notebook is probably enough.

2

Uncertainty rules are the product

Instructions for missing approvals, conflicting documents, out-of-scope questions and pressure are what separate a coach from a cheerleader.

3

Advisory, not automatic

The agent rates, cites and drafts. People approve contracts, place POs and send fan emails. Keep that line visible in the agent's output.

Dugout notes

Dugout notes · instructor answer key

Timing (30 min): 4 min why agents + saved prompt vs agent · 3 min Describe demo · 7 min configure · 5 min preview test and refine · 8 min Break the Agent · 3 min sharing and advisory vs automation.

Expected assessment (from knowledge only): Towels YELLOW (approvals and plan in place, but inventory is UNVERIFIED from knowledge alone; a strict agent that says YELLOW is applying its own GREEN rule correctly) · Fireworks GREEN (vendor service) · Bobbleheads YELLOW (contract and plan fine; fulfillment UNVERIFIED without the delivery file) · Mini bats YELLOW (distribution conflict) · BRE bucket hat RED (not in the locked plan, amendment unsigned per sponsor summary, no Ops sign-off). Note that the agent's knowledge predates the plot twist memo, which is another good teaching point.

Staffing catch: if a tester mentions the memo's "9 extra staff," a great agent applies the playbook rule (+3 per dual-item gate) and flags that the redlined scope implies 15.

Most common failure: test 2. Agents tend to answer from the Event Plan because it's more specific. The fix is the explicit "compare documents" step plus "report conflicts, never choose silently".

Most common instruction fix: adding "A conditional approval counts as NOT MET" and "A signed contract is not an approval" (both already in the blueprint; remove them for a live before/after demo).
